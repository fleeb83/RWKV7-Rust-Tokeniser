# RWKV7 Rust Tokeniser

A pure Rust tokenizer for RWKV models, including RWKV-7 models that use
`rwkv_vocab_v20230424`. Zero runtime dependencies. The official vocabulary is
bundled and embedded in your executable; no download or runtime file is needed.

## Add it to your app

Clone this repository beside your Rust app, then add to your app's `Cargo.toml`:

```toml
[dependencies]
rwkv-tokenizer = { path = "../RWKV7-Rust-Tokeniser" }
```

## Load it alongside your model

Create the tokenizer once when you load your model weights, then reuse it:

```rust
use std::{error::Error, io};
use rwkv_tokenizer::RwkvTokenizer;

fn main() -> Result<(), Box<dyn Error>> {
    let tokenizer = RwkvTokenizer::bundled()
        .map_err(|e| io::Error::new(io::ErrorKind::InvalidData, e))?;

    let ids = tokenizer.encode("User: hello\n\nAssistant:")?;
    // Pass ids to your RWKV runtime's model forward/prefill call.
    // Decode the token IDs generated by the model in the same way:
    let text = tokenizer.decode_utf8(&ids)?;
    println!("{text}");
    Ok(())
}
```

This crate handles tokenization only. Load weights and run generation through
your chosen RWKV runtime. Use the prompt format required by your model.

- Only use this vocabulary with a model trained for it; it is not the older
  `20B_tokenizer.json` tokenizer.
- Handle token ID `0` as end-of-text in your generation loop before decoding.
  It has no text entry and decoding it returns an error.
- For streaming, use `decode_bytes` and buffer bytes until they form valid
  UTF-8. One token can contain only part of a character.
- To use an explicit external vocabulary, call
  `RwkvTokenizer::from_file(std::path::Path::new("/path/to/vocab.txt"))`.
  It must follow the RWKV World format and token ordering.

## Try it

Install Rust stable and run from this directory:

```sh
cargo run --example usage --locked
cargo test --locked
```

On Windows, Rust's MSVC toolchain needs Visual Studio C++ Build Tools and a
Windows SDK. Python is needed only for the optional
[reference checks and benchmarks](benchmark/README.md).

## Tentative performance

An earlier CPU-only run on an AMD Ryzen 7 9700X under Linux/WSL2 compared
Rust with BlinkDL's Python `TRIE_TOKENIZER` (Python 3.12.14). Each ran for
five minutes over the same 76-case corpus, with exact token-ID and byte parity.

| Operation time | Rust | Python TRIE |
|---|---:|---:|
| Encode median | 2.695 µs | 12.413 µs |
| Encode p95 | 1.043 ms | 6.042 ms |
| Decode median | 0.461 µs | 2.866 µs |
| Decode p95 | 100.820 µs | 805.808 µs |

These are individual encode/decode call timings across mixed input sizes,
excluding conversion and result validation. Lower is better; p95 is the time
at or below which 95% of calls finished.

Treat these as preliminary: the run predates vocabulary bundling, the Rust
compiler version was not recorded, and the current package has not had a new
five-minute performance run. Process startup and resource measurement differed
between harnesses, so these figures do not establish end-to-end throughput or
memory savings. See the [recorded run](benchmark/HISTORICAL.md) and
[reproduction instructions](benchmark/README.md).
